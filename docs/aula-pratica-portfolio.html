Como usar esta aula

Siga na ordem. Cada bloco de código tem antes um parágrafo dizendo para que ele serve, o caminho do arquivo no cabeçalho e um botão Copiar. Os comentários dentro do código explicam linha a linha. Todos os comandos são executados na raiz do projeto (a pasta que já tem docs/ e CLAUDE.md), no PowerShell ou no terminal do VS Code.

Dica: no VS Code, ao criar um arquivo digitando o caminho completo (ex.: src/components/Secao/Secao.jsx), as pastas são criadas automaticamente.

1Visão geral da tecnologia

O que vamos construir

Uma página única (single page) em React com cinco seções. O menu do topo leva a cada seção por âncora (#projetos, #contato…), destaca a seção visível e vira um menu "hambúrguer" no celular. Todo o conteúdo (textos, projetos, habilidades) fica em arquivos de dados, e os componentes só sabem exibir esses dados.

Por que React + Vite + CSS Modules

React permite montar a página com componentes reutilizáveis: o mesmo CardProjeto serve para 3 ou 30 projetos. Vite cria o projeto e gera o build de produção em segundos. CSS Modules é a estilização modular pedida no enunciado: cada componente tem seu .module.css, e o Vite renomeia as classes (ex.: card vira _card_x7f2), então duas classes .titulo em arquivos diferentes nunca se chocam. Não precisa instalar nada a mais.

Versões fixas

A aula foi testada com Node 24, create-vite 9.3.1, Vite 8.3.5, React 19.3.1 e oxlint 1.89.0. O package.json usa versões exatas (sem ^) para que o seu projeto instale exatamente o que foi testado. Use Node 20.19 ou mais novo (o Vite 8 não roda em versões antigas).

2Estrutura final

A organização é por responsabilidade, um dos critérios de avaliação: data/ guarda o conteúdo, components/ guarda peças reutilizáveis usadas por várias seções, sections/ guarda as cinco partes da página e hooks/ guarda a lógica reutilizável. Cada componente tem uma pasta com o .jsx e o .module.css lado a lado, então o estilo fica sempre junto de quem o usa.

3Criar o projeto

O create-vite se recusa a criar o projeto numa pasta que já tem arquivos (a nossa tem docs/ e CLAUDE.md): no modo automático ele responde "Operation cancelled" e, no modo interativo, oferece apagar tudo. Por isso criamos o projeto numa subpasta portfolio e depois movemos o conteúdo dela para a raiz. Em seguida apagamos os arquivos de exemplo que o modelo traz e não vamos usar.

Nunca escolha "Remove existing files"

Se rodar o create-vite sem --no-interactive direto na raiz, ele pergunta o que fazer com a pasta não vazia. A opção de remover arquivos apaga a pasta docs/ com esta aula.

Substitua o package.json gerado por este. A única diferença real são as versões exatas, sem o ^: com ^, o npm pode instalar uma versão mais nova do que a testada, e um projeto de portfólio precisa continuar compilando igual daqui a meses. O script lint roda o oxlint, o verificador de código que o Vite agora traz no lugar do ESLint.

Com o package.json pronto, instale as dependências. O npm cria a pasta node_modules (que não vai para o GitHub, por causa do .gitignore) e o package-lock.json, que registra a versão exata de cada pacote e deve ir para o repositório. Ainda não rode o projeto: o App.jsx do modelo importa arquivos que acabamos de apagar.

Confira: o terminal termina com found 0 vulnerabilities.

4Base: HTML, entrada e estilo global

O index.html é a única página HTML do site: o React desenha tudo dentro da div#root. Edite só o começo do arquivo, da primeira linha até <body>: trocamos o idioma para pt-BR (ajuda leitores de tela e o corretor), o título da aba e acrescentamos a descrição exibida pelo Google e pelo LinkedIn. O resto do arquivo continua igual.

Não apague a div id="root" nem a linha script type="module" src="/src/main.jsx" que vêm depois do <body>: é por ela que o navegador carrega o React.

O main.jsx é o ponto de entrada: pega a div#root e renderiza o App nela. A mudança em relação ao modelo é importar ./styles/global.css em vez do index.css apagado. O StrictMode só existe em desenvolvimento e roda alguns efeitos duas vezes de propósito, para revelar efeitos sem limpeza.

Este é o único CSS global. Ele define as variáveis de cor e tamanho (todos os módulos usam var(--cor-destaque), então trocar o tema é mudar uma linha) e um reset mínimo. O scroll-behavior: smooth faz o clique no menu rolar suavemente, e o scroll-margin-top impede que o cabeçalho fixo cubra o título da seção ao chegar nela.

5Dados e imagens

Separar o conteúdo da interface evita repetição e facilita a manutenção: nome, e-mail e links aparecem em várias seções, mas são escritos uma vez só aqui. O array secoes define a ordem e os rótulos do menu; cada id precisa ser igual ao id usado na seção correspondente. Troque os textos pelos seus dados reais antes de publicar.

A lista de projetos é o coração do portfólio. Cada objeto vira um card, com título, descrição, imagem, tecnologias e links. As imagens são importadas: assim o Vite confere no build se o arquivo existe e gera o caminho final certo. Escolha projetos do curso com tecnologias diferentes (o enunciado avalia a variedade) e use demo: null quando o projeto não tiver versão publicada.

As habilidades ficam agrupadas por categoria para a seção não virar uma sopa de etiquetas: o recrutador bate o olho e encontra "React e ecossistema" ou "Estilização". A seção vai percorrer este array com map duas vezes, uma para os grupos e outra para os itens de cada grupo. Ajuste a lista ao que você realmente sabe usar.

Para o projeto compilar desde já, criamos imagens provisórias em SVG (texto puro, dá para copiar). Este é o avatar da seção Sobre mim. Depois troque por uma foto sua: salve, por exemplo, src/assets/foto.jpg e mude o import em Sobre.jsx para esse arquivo. Uma foto quadrada de uns 400×400 px é suficiente.

Esta é a captura provisória de um projeto: um desenho de navegador em proporção 16:9, a mesma usada pelo card. Salve como efood.svg e use o comando a seguir para criar as outras três cópias. O ideal é substituir cada uma pela captura de tela real do seu projeto (tecla Win+Shift+S no Windows).

Este comando cria as imagens dos outros três projetos copiando a primeira. Os nomes precisam ser exatamente os usados nos import de projetos.js; se um nome não bater, o build falha com "Could not resolve". Quando trocar por capturas reais em .png, lembre-se de mudar também a extensão no import.

6Componentes reutilizáveis

Antes das seções, criamos as peças que elas vão compartilhar. É aqui que o critério "componentes, hooks e props sem repetições desnecessárias" é atendido.

Por que separar dados e componentes

❌ HTML repetido em cada card

  1. Copiar o mesmo <article> três vezes
  2. Mudar o layout = editar três lugares
  3. Adicionar um projeto = colar mais JSX
Código longo e fácil de ficar inconsistente

✅ Um componente + um array

  1. CardProjeto recebe os dados por props
  2. projetos.map(...) cria um card por item
  3. Adicionar um projeto = um objeto a mais
Layout em um lugar só, conteúdo em outro

A Secao é a moldura comum a Sobre, Projetos, Habilidades e Contato: aplica o id usado pelas âncoras do menu, o título h2 e a largura máxima. O que muda de uma seção para outra chega pela prop children. O aria-labelledby liga a seção ao seu título, para o leitor de tela anunciar "região Projetos".

O CSS Module da seção. Repare que as classes têm nomes simples, como .titulo: o Vite transforma cada uma num nome único no build, então outro arquivo pode ter a sua própria .titulo sem conflito. O clamp() faz o título crescer com a tela sem precisar de media query, e o ::after desenha o traço azul abaixo dele.

A Etiqueta é a "pílula" usada tanto nas tecnologias de cada projeto quanto na lista de habilidades. É um componente minúsculo, mas evita escrever o mesmo estilo em dois lugares. Ele devolve um <li>, então sempre deve ser usado dentro de um <ul>, o que deixa a lista semântica para leitores de tela.

Estilo da etiqueta: fundo azul transparente, borda e cantos totalmente arredondados com border-radius: 999px. O list-style: none remove a bolinha que o navegador coloca em todo <li>. As cores vêm das variáveis do global.css para manter o tema consistente em todo o site.

O CardProjeto recebe cada campo do projeto por props (desestruturadas na assinatura) e monta imagem, título, descrição, tecnologias e links. Duas técnicas importantes aparecem aqui: map com key para listar as tecnologias e renderização condicional (demo && …) para só mostrar "Ver online" quando existe demonstração.

O card é uma coluna flex. O aspect-ratio: 16 / 9 com object-fit: cover deixa todas as imagens do mesmo tamanho, mesmo que as capturas tenham proporções diferentes. O flex: 1 no corpo e o margin-top: auto nos links empurram os botões para o rodapé, alinhando os cards lado a lado mesmo com descrições de tamanhos diferentes.

A rolagem é do próprio navegador (âncora + CSS). O React só cuida de destacar o link certo, inclusive quando o usuário rola com o mouse.

Este hook personalizado descobre qual seção está no meio da tela. Ele usa useState para guardar o id ativo e useEffect para criar um IntersectionObserver, API do navegador que avisa quando um elemento entra numa área da tela. A função devolvida pelo efeito desliga o observador quando o componente sai da tela, evitando vazamento de memória.

O cabeçalho monta o menu a partir do array secoes, usa o hook para destacar o link ativo e guarda em useState se o menu do celular está aberto. A lista de ids é criada fora do componente de propósito: se fosse criada dentro, seria um array novo a cada render e o useEffect do hook recriaria o observador toda hora.

O cabeçalho usa position: sticky para ficar preso no topo. No desktop o menu é uma linha; abaixo de 720px o botão hambúrguer aparece e o menu vira uma coluna escondida, que só ganha display: flex quando o React soma a classe aberto. É assim que estado (React) e estilo (CSS Module) conversam.

8Seções Início e Sobre mim

O Início é a página inicial com o resumo profissional pedido no enunciado. Ele não usa a Secao porque não tem título h2: o nome é o único h1 da página, o assunto principal do site. Os dois botões são âncoras para Projetos e Contato, os dois lugares onde um recrutador mais quer chegar.

O min-height faz o Início ocupar a primeira tela inteira, descontando a altura do cabeçalho, e o flex centraliza o conteúdo na vertical. O nome usa clamp() para ir de 2.4rem no celular até 4.5rem no desktop sem quebrar o layout, e os botões usam flex-wrap para descer de linha em telas estreitas.

Sobre mim reúne apresentação, foto e informações de contato, como pede o enunciado. Os parágrafos vêm de perfil.sobre com map, e os contatos usam <dl> (lista de definições), a tag certa para pares rótulo/valor. O texto alternativo da foto é montado com o nome, então continua correto se você trocar o nome no perfil.

No celular a grade tem uma coluna (foto centralizada em cima, texto embaixo); a partir de 768px vira duas colunas. Esta é a abordagem mobile first: o estilo padrão é o do celular e a media query só acrescenta o layout de desktop. O overflow-wrap: anywhere quebra links longos e evita rolagem horizontal.

9Seções Projetos e Habilidades

A seção Projetos fica curta porque o trabalho pesado está no CardProjeto e nos dados. O {...projeto} (spread) passa cada campo do objeto como uma prop: é o mesmo que escrever titulo={projeto.titulo}, descricao={projeto.descricao} e assim por diante. A key usa o id do projeto, que é único e estável.

Uma linha de CSS resolve a responsividade da grade: repeat(auto-fill, minmax(300px, 1fr)) coloca quantas colunas de pelo menos 300px couberem. O min(300px, 100%) garante que, num celular muito estreito, a coluna nunca passe da largura da tela e crie rolagem horizontal.

Habilidades percorre os grupos e, dentro de cada grupo, os itens: um map dentro de outro. Cada nível tem a sua key (o nome da categoria e o nome do item). A mesma Etiqueta dos cards de projeto é reaproveitada aqui, então as duas seções ficam visualmente coerentes sem duplicar estilo.

Os grupos usam a mesma técnica de grade automática dos projetos, com mínimo de 240px por coluna: quatro colunas no desktop largo, duas em tablets e uma no celular. Cada grupo é um bloco com fundo de superfície e borda, e a lista interna usa flex-wrap para as etiquetas quebrarem de linha.

Três estados (campos, erros, enviado) descrevem tudo o que a tela mostra.

O formulário é controlado: cada campo mostra o valor guardado em useState e avisa o React a cada tecla. Ao enviar, a função validar devolve os erros; se não houver nenhum, o código monta um link mailto: com assunto e mensagem e abre o programa de e-mail do visitante. Assim o formulário funciona de verdade sem precisar de back-end.

Quer receber as mensagens sem depender do e-mail do visitante?

Serviços gratuitos como Formspree ou EmailJS recebem o formulário e mandam para o seu e-mail. Para usar, troque a linha do window.location.href por um fetch para o endereço que o serviço fornecer. Não é obrigatório para a entrega.

Estilo do formulário. O seletor [aria-invalid='true'] pinta de vermelho a borda dos campos que o React marcou como inválidos: o mesmo atributo que avisa o leitor de tela também controla o visual, sem precisar de uma classe extra. O resize: vertical deixa o visitante aumentar a caixa de mensagem só na altura.

A seção Contato junta o formulário e os links para redes profissionais (o enunciado aceita um ou outro; ter os dois é melhor). O array redes é montado a partir do perfil, então o endereço do LinkedIn e do GitHub continua escrito num lugar só. Os links externos abrem em nova aba com rel="noreferrer".

No celular, texto e formulário ficam um embaixo do outro; a partir de 768px viram duas colunas, com o formulário um pouco mais largo (1.4fr). Os links das redes são botões com borda que mudam de cor no :hover, deixando claro que são clicáveis.

O rodapé mostra o ano atual e o nome. O cálculo do ano fica fora do componente: o React espera que a função do componente seja pura (mesmas props, mesmo resultado), e o oxlint avisa quando você chama new Date() durante o render. Fora dele, o valor é calculado uma vez ao carregar a página.

Estilo do rodapé: texto pequeno, centralizado, na cor suave e com uma linha separando do conteúdo. O margin: 0 no parágrafo remove a margem padrão que o navegador coloca em todo <p>, deixando o espaçamento controlado só pelo padding do rodapé.

13Build de produção

O build gera a versão otimizada que vai para o ar: o Vite junta e minifica JS e CSS na pasta dist/, renomeia as classes dos CSS Modules e confere se todo import existe. Rode o lint antes, para pegar erros de React (como hooks fora de lugar), e o preview depois, para ver exatamente o que a Vercel vai publicar.

Repita no preview os testes de navegação e formulário da seção anterior. A pasta dist/ não vai para o GitHub (está no .gitignore): a Vercel gera a dela.

14README.md

O README é a porta de entrada do repositório e um entregável avaliado: precisa explicar como rodar localmente, trazer o link da versão online e descrever os projetos apresentados. Substitua o README gerado pelo Vite por este e troque os dados de exemplo pelos seus. 15Publicar no GitHub

Antes, crie no GitHub um repositório público e vazio (sem README, sem .gitignore, para não dar conflito com o seu), por exemplo ebac-portfolio. Os comandos abaixo transformam a pasta num repositório git, fazem o primeiro commit e enviam para o GitHub. Troque seu-usuario pelo seu usuário em todos os lugares.

docs/ e CLAUDE.md também vão para o repositório

Com o git add ., a pasta docs/ (enunciado e esta aula) e o CLAUDE.md entram no commit. Não atrapalha o deploy. Se preferir deixar o repositório só com o portfólio, rode Add-Content .gitignore "docs/", "CLAUDE.md" antes do git add ..

16Deploy na Vercel

A Vercel é gratuita para projetos pessoais, reconhece projetos Vite sozinha e publica de novo a cada git push.

  1. Acesse vercel.com e clique em Sign Up → Continue with GitHub.
  2. No painel, clique em Add New… → Project e, em Import Git Repository, escolha ebac-portfolio (se não aparecer, clique em Adjust GitHub App Permissions e libere o repositório).
  3. Confira a configuração: Framework Preset = Vite, Build Command = npm run build, Output Directory = dist, Root Directory = ./. Não mude nada.
  4. Clique em Deploy e aguarde (menos de 1 minuto). No fim aparece a tela de parabéns com a miniatura do site.
  5. Abra o domínio gerado (algo como ebac-portfolio.vercel.app) e repita os testes da seção 12. Para um nome melhor, vá em Settings → Domains e edite o subdomínio.

Com o link definitivo em mãos, falta colocá-lo no README, que é onde o enunciado pede que ele esteja. Edite a linha "Versão online" do README.md com o endereço real e envie a alteração. Esse push também dispara um novo deploy automático na Vercel, que você pode acompanhar na aba Deployments.

Entrega: o link do repositório (https://github.com/seu-usuario/ebac-portfolio) com o link do site dentro do README.
